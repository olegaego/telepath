# Ретранслятор пушей Agentgram

Telegram присылает пуши сторонним приложениям на iPhone только через Web Push: на адрес, который назовёт само приложение. Отправлять пуши в Apple может только владелец приложения. Этот маленький сервер стоит посередине: принимает пуш от Telegram и передаёт его в Apple.

## Что он хранит

Ничего. Базы нет.

Адрес, который приложение отдаёт Telegram, приложение собирает само: в адрес зашит токен Apple этого телефона, зашифрованный открытым ключом ретранслятора. Прочитать его может только ретранслятор. Телефон с ретранслятором никогда не связывается.

## Что он видит

Только шифр. Telegram шифрует пуш дважды: снаружи для ретранслятора (Web Push), внутри ключом аккаунта, который есть только у телефона. Ретранслятор снимает внешний слой и передаёт Apple внутренний шифр как есть. Расшифровывает его расширение уведомлений на телефоне. Пуш, который Telegram не зашифровал ключом аккаунта, ретранслятор не передаёт.

В памяти он держит только счётчик пушей за последнюю минуту, чтобы один телефон нельзя было завалить пустыми пушами.

## Как поднять свой

Нужны Node.js 20+ и ключ Apple Push Notifications (.p8) из аккаунта разработчика того, кто собирает приложение.

```sh
node relay.mjs keygen
```

Покажет закрытый ключ для ретранслятора и две строки для сборки приложения. Ретранслятор запускается с настройками из окружения:

| Переменная | Что это |
|---|---|
| `RELAY_PRIVATE_KEY` | закрытый ключ из `keygen` |
| `RELAY_AUTH` | `push_relay_auth` из `keygen` |
| `APNS_KEY_FILE` | путь к ключу Apple .p8 |
| `APNS_KEY_ID`, `APNS_TEAM_ID` | номер ключа и команды Apple |
| `APNS_TOPIC` | bundle id приложения |
| `PORT` | порт, по умолчанию 8096 |

Снаружи нужен HTTPS. В настройках сборки приложения (`build-system/…-configuration.json`):

```json
"push_relay_url": "https://ваш-адрес",
"push_relay_key": "открытый ключ из keygen",
"push_relay_auth": "auth из keygen"
```

Если эти поля пустые, приложение регистрирует пуши как обычный Telegram.
